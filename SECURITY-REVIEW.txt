BRAINMETRIC SECURITY REVIEW — HARDENED STATIC PWA (v7 RESET/THEME UPDATE)
Build date: 2026-10-18

THREE SECURITY PASSES
1) Browser execution and origin boundary
   - Removed the Google Fonts import and external font dependency.
   - Moved the main executable inline script to same-origin app.js.
   - Moved all inline stylesheet blocks to same-origin CSS files.
   - Added a Netlify _headers policy: CSP blocks inline scripts, inline event handlers,
     objects, frames and external network connections; browser headers also restrict
     framing, content sniffing, referrers, permissions and cross-origin reuse.
   - Inline style attributes remain permitted for existing dynamic layout styles; inline
     script execution does not. No inline event-handler attributes were present in the HTML.

2) Local data integrity and robustness
   - Bound local-storage record size and collection lengths.
   - Normalized profile fields, dates, numbers, settings, scores and stored list values.
   - Invalid/corrupt storage falls back to clean defaults instead of being trusted blindly.
   - All locally stored values remain user-editable. This prevents malformed saved data
     from being treated as trusted input; it does not provide tamper-proof scores.

3) Offline cache containment
   - Versioned the cache and precaches only known same-origin application files.
   - Ignores non-GET and cross-origin requests; does not cache query-specific challenge URLs.
   - Deletes only old BrainMetric cache versions and has a static allow-list for cache writes.

SECURITY LIMITS
- This is a static account-free PWA. A visitor can inspect the downloaded question bank and
  change their own local scores/XP. Do not use client-side results for cash prizes, official
  examinations, or a trusted public leaderboard. Those need server-side validation.
- Local browser storage is not a secure vault and may be cleared by the browser.
- CSP and HSTS are configured for Netlify's _headers support. If hosted elsewhere, configure
  equivalent HTTP response headers at that host. HSTS requires HTTPS; publish via HTTPS.
- No penetration test or audit of the live deployed origin has been performed. The checks
  described here are source/package checks, not a guarantee of zero vulnerabilities.
